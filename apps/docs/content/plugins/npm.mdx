The npm plugin is enabled by default. It discovers workspace packages, bumps versions in `package.json`, updates dependency ranges, and publishes to npm.

## Discovery

Tegami scans:

- The root `package.json` (if present).
- Workspace packages from the `workspaces` field in the root manifest.
- `pnpm-workspace.yaml` for pnpm projects and Nub's pnpm-compatible mode.
- `aube-workspace.yaml` for aube projects.
- The `workspace` field in `deno.json`/`deno.jsonc` for Deno projects. Members without a `package.json` (e.g. JSR-only packages) are ignored.

Deno is detected from `deno.lock`; set `client: "deno"` explicitly if your project has no lockfile. Since `deno publish` targets JSR, Tegami publishes through the npm CLI, and lockfile updates run `deno install`.

Private packages are versioned but not published unless you set `publish: true` in `packages`.

## Configuration

Pass options through the top-level `npm` field:

```ts
const paper = tegami({
  npm: {
    client: "pnpm",
    updateLockFile: true,
    onBreakPeerDep: "set",
  },
});
```

### Trusted Publishing

Tegami can bootstrap new packages under [npm trusted publishing](https://docs.npmjs.com/trusted-publishers) with `tegami npm pretrust`.

Enable the command in your Tegami config:

```ts title="scripts/tegami.mts"
const paper = tegami({
  plugins: [github({ repo: "acme/widgets" })],
  npm: {
    trustedPublish: {
      provider: "github",
      workflow: "publish.yml",
    },
  },
});
```

Use `provider: "gitlab"` with the [GitLab plugin](/plugins/gitlab) for GitLab CI. The `workflow` value is the filename passed to `npm trust --file`.

Trusted publishing only exists on `registry.npmjs.org`. Packages pointed at [another registry](#private-registries) are listed as skipped and left untouched.

#### One-time setup for new packages

Run this locally:

1. Run `tegami version` so a publish lock exists.
2. Login to npm (`npm login`).
3. Run `tegami npm pretrust` (add `--dry-run` to preview).

For each publishable package in the lock that npm does not know yet, pretrust:

- Publishes an empty placeholder at `0.0.0-tegami-trusted-publish-setup` under the `temp` dist-tag.
- Runs `npm trust` to link the package to your CI workflow.
- Writes `npm:mark-latest` to the publish lock so the first real release is tagged `latest`.

Packages already on the registry are skipped.

CI still needs `id-token: write` in GitHub Actions (see [CI setup](/ci)). After pretrust, commit your local changes and hand the actual publishing to CI.

## Dependency bumps

When a package is bumped, the plugin may bump its dependents based on dependency kind:

- `dependencies` and `optionalDependencies` → patch bump on the dependent
- `devDependencies` → no automatic bump
- `peerDependencies` → major bump (or handled by `onBreakPeerDep`)

Customize this with `bumpDep`:

```ts
npm({
  bumpDep: ({ kind }) => (kind === "dependencies" ? "patch" : false),
});
```

## Package options

It allows to override `distTag` for npm publish, otherwise, it will read from your `publishConfig` in `package.json`.

When publishing prerelease versions, npm 11+ requires an explicit dist-tag. Tegami infers one from your `prerelease` config (for example, `1.0.0-alpha.0` → `alpha`) when no tag is configured.

```ts
tegami({
  packages: {
    "@acme/ui": {
      npm: {
        distTag: "next",
      },
    },
  },
});
```

### Aliases

Publish a package under extra names, for example to keep an unscoped name alive after moving to a scope:

```ts
tegami({
  packages: {
    "@acme/ui": {
      npm: {
        alias: ["acme-ui"],
      },
    },
  },
});
```

An alias is not a separate package. It shares the version, changelog, git tag, and dist-tag of `@acme/ui`, changelog files keep referencing `@acme/ui`, and so do workspace dependents.

Each name is published from the package directory, with `name` in `package.json` swapped to the alias for the duration of the publish. Lifecycle scripts such as `prepublishOnly` run again for every name on purpose: a build that imports `package.json` picks up the alias, and a bundler config can branch on the name to ship a different build under each one. Plugin `willPublish` hooks run once per package before any swap, so builds that differ per name belong in lifecycle scripts.

Names the registry already has are skipped, so a failed alias publish can be retried on its own.

The registry of an alias is resolved from its own name, so a scoped alias follows the `@scope:registry` entry of its scope. `tegami npm pretrust` sets up [trusted publishing](#trusted-publishing) for aliases as well.

## Private registries

Tegami resolves a package's registry the way npm does, taking the first of:

1. `publishConfig.registry` in the package manifest.
2. `@scope:registry` in `.npmrc`.
3. `registry` in `.npmrc`.
4. `https://registry.npmjs.org`.

Both your user-level & project-level `.npmrc` are read.

Registries other than npm usually need credentials to be read as well, so Tegami sends the token you configured for the host:

```ini title=".npmrc"
@acme:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${NODE_AUTH_TOKEN}
```

`${VAR}` is read from the environment, and an entry pointing at an unset variable is dropped instead of being sent empty.

`actions/setup-node` already writes that file for you in GitHub Actions:

```yaml
- uses: actions/setup-node@v6
  with:
    node-version: 24
    registry-url: https://npm.pkg.github.com
    scope: "@acme"

- name: Version & publish packages
  run: pnpm tegami ci
  env:
    GITHUB_TOKEN: ${{ github.token }}
    NODE_AUTH_TOKEN: ${{ github.token }}
```

<Callout type='warn' title="GitHub Packages">

Publishing to GitHub Packages needs `packages: write` on top of the [permissions](/ci) the workflow already has. It answers a rejected read with `404` rather than `401`, so a missing or wrong token makes a package look unpublished. Check the token first when publish then fails on authentication.

</Callout>
